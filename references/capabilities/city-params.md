# 城市参数卡（模板 + 已核实示例）

> 这张卡不提供「全国统一答案」，它提供**每个城市必须单独核的六个参数**、官方入口、以及已经核实过的片段。未核实的参数一律标 `[需现查]`，不许用别的城市的值替代。


## 必答要点（先看这 6 行）

- 六参数：居住证 / 学位 / 公积金 / 短租 / 资金监管 / 50% 线
- 先问用户：有没有联网搜索、是否授权检索
- 无授权：只给官方入口 + 需现查，不给数字

> 回答末尾必须逐条复述以上要点（已覆盖 / 不适用+原因），缺一条视为未完成。

## R — 原文 (Reading)

> "设区的市级以上地方人民政府应当建立住房租金监测机制，定期公布本行政区域内不同区域、不同类型住房的租金水平信息。"
> — 《住房租赁条例》第二十九条

> "租赁住房单间租住人数上限和人均最低租住面积，应当符合设区的市级以上地方人民政府规定的标准。"
> — 《住房租赁条例》第七条

## I — 方法论骨架 (Interpretation)

同一部国家法，落到城市会分叉成六组参数：居住证的**材料与时限**、学位的**积分规则**、公积金的**额度与频次**、短租的**禁限区域**、租金押金的**监管口径**、小额诉讼的**50% 工资线**。判断一个城市能不能办、能办多少，不能看全国条文，要看这六项。做法是：先锁定城市与区，再按「国家条件 → 城市细则 → 区级执行」三层核对，每项记录**查询日期 + 来源链接**，因为这类参数每年调整。已核实片段可以直接引用；未核实的必须在回答里显式标注「需现查」，并给出查询入口，而不是编一个看起来合理的数字。

## A1 — 应用示例

### 示例 1：在南京租房，要办居住证、孩子上学、提公积金
- **类型与来源**：合成演练（国家条件已核实，城市材料需现查）。
- **输入**：南京市某区，租房 1 年，孩子 6 岁，正常缴公积金。
- **方法论的使用**：① 居住证：国家条件=居住半年+合法稳定住所（租赁合同/备案可作证明），材料以南京公安/政务网为准 `[需现查]`；② 学位：查该区教育局当年招生政策与积分表 `[需现查]`；③ 公积金：租房提取额度与频次以南京公积金中心公告为准 `[需现查]`；④ 短租不适用；⑤ 监管口径查南京住建；⑥ 小额诉讼线查江苏省上年度平均工资。
- **结论**：能办，但每一项都要落到南京/该区的入口；回答里给「入口 + 材料框架 + 需现查标记」。
- **结果**：合成演练。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 问「我们这座城市居住证要什么材料」「孩子能上哪个学校」。
2. 问「公积金能提多少」「补贴多少」。
3. 想确认某城市短租是否合法、押金是否受监管。

### 语言信号

- "我们这儿" / "我在 XX 市" / "这个区"
- "要什么材料" / "能提多少" / "能上哪所学校"
- "local rules" / "residence permit requirements"

### 与相邻能力的区分

- 与 `public-services` 的区别：那张卡给全国流程与顺序，本卡给「城市参数怎么查、查到什么程度」。
- 与 `rights-and-benefits` 的区别：本卡不处理纠纷，只提供参数与入口。

## E — 可执行步骤 (Execution)

**必需输入**：城市、区（学位与居住证常到区级）、办理事项、是否有子女/社保/毕业年份。

**交付物与完成标准**：一张六行参数表（参数 / 数值或结论 / 来源链接 / 查询日期 / 是否需现查）。

1. **锁城市与区**
   - 完成标准：明确「市 + 区」，因为学位与居住证材料常由区级执行。
2. **逐项核六参数**
   - 完成标准：每项给出「已核实值」或 `[需现查]` + 官方入口，不允许留空或套用其他城市。
3. **标注时效**
   - 完成标准：写明查询日期；政策类注明「以提交当月公告为准」。

### 六参数表（模板）

| 参数 | 查什么 | 官方入口 | 已核实片段 |
|---|---|---|---|
| 居住证 | 材料清单、居住登记满几个月、是否需备案 | 市公安局/政务网/社区服务站 | 国家条件：居住半年 + 合法稳定就业/住所/连续就读之一（《居住证暂行条例》第 2 条）；城市材料 `[需现查]` |
| 学位 | 积分规则、报名时间窗、是否需要社保年限 | 区教育局招生专栏 | `[需现查]`（区级每年调整） |
| 公积金 | 租房提取额度、频次、材料 | 市公积金中心 | 2025 年国务院修改条例后取消「房租超工资比例」门槛；额度 `[需现查]` |
| 短租 | 是否禁限区域、是否需业主同意/公安登记 | 市住建 + 公安 | 北京：核心区禁止，其他区域需业主同意并登记，个人违者罚 2000–10000 元 |
| 资金监管 | 收租/押金超限是否强制监管 | 市住建 | 广州：单次收租 >3 个月或押金 >1 个月，超额纳入监管；深圳/上海/北京另有细则 |
| 小额诉讼线 | 上年度就业人员年平均工资 × 50% | 省统计局/高院公告 | `[需现查]`（每年更新） |

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 只问全国通用规则：直接看 `public-services` 与 `legal-basis`，不必查城市。
- 需要法律意见：转 12348。

### 常见误用

- 拿一线城市的额度套三四线：公积金、补贴、学位积分差异极大。
- 用去年的公告回答今年的问题：政策类必须以提交当月为准。
- 把「能办」说成「能上」：学位取决于积分与学位供给，不承诺结果。

### 盲点 / 局限

- 本卡不自带全国城市数据库；未核实城市只能给入口与框架。
- 区级执行口径可能比市级更严，需以区教育局/派出所答复为准。

## 检索前置确认（必须做，不能跳过）

城市参数只能现查，所以每次涉及具体城市，先走这三步：

1. **问能力**：「你这边能联网搜索吗？就是 agent 里有没有 search 插件或联网功能。」
2. **要授权**：「我想用它查一下你所在城市的居住证/公积金/学位规定，可以吗？查到的每条我都会附来源和日期。」
3. **执行**：
   - 有授权 → 检索官方来源（住建/公安/人社/公积金/教育），提炼成六参数表，标注来源与查询日期；
   - 无搜索或无授权 → 不给数字，只给官方入口 + 「需现查」，并说明为什么不能替用户猜。

禁止：未经同意就检索；把检索到的旧公告当现行政策；把别城数据套到用户城市。
